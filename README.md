# Online Appointment & Records System for a Local Clinic

CSE 220 — Principles of Software Engineering | Final Course Project

This repository documents the full project lifecycle for a proposed online appointment and records management system for a local clinic, simulating real-world Agile and configuration management practices without a coding implementation, per the course assignment.

## Project Summary

- **Problem:** The clinic currently relies on phone-based booking, a handwritten appointment register, and paper patient files, leading to double bookings, slow record access, and manual billing errors.
- **Agile Methodology:** Scrum — an 8-story product backlog split across two sprints, tracked on Trello.
- **Requirements Engineering:** Gathered via a receptionist interview and a patient questionnaire (Google Forms). See `/requirements`.
- **System Design:** Modeled with four UML diagrams — Use Case, Class, Activity, and Sequence. See `/design`.
- **Testing:** 21 test cases across Patient, Doctor, and Receptionist modules, covering unit, integration, system, and user acceptance testing. See `/testing`.

## Version Control Workflow

This repository was maintained using standard Git practices as required by the assignment:

- Descriptive commit messages for each addition (e.g. `Add functional and non-functional requirements`, `Add UML diagrams`, `Add test case matrix`)
- Multiple commits showing incremental progress across the project lifecycle
- A feature branch used for adding documentation, merged back into `main` via a pull request
